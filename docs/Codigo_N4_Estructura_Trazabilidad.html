2.4.1 Estructura del repositorio y módulos

El sistema se implementa en dos módulos principales alineados con el Nivel 2 (Contenedores): una aplicación web SPA (JavaScript vanilla, patrón MVC) como canal del cliente, y un Backend en Node.js (Express + Sequelize ORM + PostgreSQL) que centraliza la lógica de negocio, autenticación, pasarela de pagos, gestión de inventario e integraciones externas.

2.4.2 Trazabilidad paquetes/Clases

Para garantizar consistencia entre arquitectura y código, los componentes del Nivel 3 se evidencian en los siguientes módulos para los procesos de Autenticación y Gestión de Usuarios, Gestión de Pedidos y Gestión de Inventario:

Proceso 1: Autenticación y Gestión de Usuarios

Elemento N3 Código (paquete/clase) Responsabilidad
API de Inicio de Sesión routes/auth.js Expone endpoints de login (POST /auth/login), registro (POST /auth/register), verificación de email y consulta de perfil (GET /auth/me).
Componente de Seguridad middleware/auth.js Valida credenciales JWT, gestiona sesión/token y protege endpoints con authRequired y adminOnly.
Modelo de Usuario models/User.js Sequelize + PostgreSQL (tabla: users): username, passwordHash, role (admin/client), email, emailVerified, tokens de verificación y recuperación, 2FA.
API de Gestión de Usuarios routes/users.js Gestión de perfil de usuario, actualización de datos personales (PUT /users/me), listado de usuarios (admin).
Componente de Notificaciones utils/emailService.js Dispara y gestiona notificaciones por email (SMTP/Brevo): verificación de cuenta, recuperación de contraseña, reenvío de verificación.
Recuperación de Contraseña routes/auth.js Endpoints POST /auth/forgot-password y POST /auth/reset-password: genera token temporal, envía email y permite restablecer contraseña.
Cliente HTTP (Frontend) api/client.js Gestiona token JWT en localStorage (pl_token), adjunta header Authorization: Bearer a cada request autenticado.
Modelo de Sesión (Frontend) models/appModel.js Métodos login(), logout(), init(): restaura sesión desde localStorage, valida token con /auth/me, maneja timeout de 30 minutos.
Controlador de Auth (Frontend) controllers/appController.js Gestiona formularios de login/registro, modales de autenticación, actualización de UI según estado de sesión, manejo de roles (admin/client).

Proceso 2: Gestión de Pedidos

Elemento N3 Código (paquete/clase) Responsabilidad
API de Gestión de Pedidos routes/orders.js Expone creación (POST /orders), consulta (GET /orders, GET /orders/my) y actualización de estado de pedidos. Genera número de factura.
Modelo de Pedido models/Order.js Sequelize + PostgreSQL (tabla: orders): userId, items (JSONB), total, subtotal, discount, shippingCost, status (pendiente_pago, confirmado, preparando, enviado, entregado, cancelado), invoiceNumber, paymentMethod, trackingEvents (JSONB).
Componente de Pedidos routes/orders.js
models/Promotion.js		 Reglas del pedido: cálculo de totales con descuentos y envío, transiciones de estado, validación de stock antes de confirmar, decremento de inventario.
Adaptador de Pasarela de Pagos routes/payments.js Encapsula integración con MercadoPago: creación de preferencias (POST /payments/create-preference), procesamiento de webhooks, verificación de estados de pago y simulación en sandbox.
Componente de Notificaciones de Pedido utils/emailService.js Envío de email de confirmación de pedido y factura al cliente tras completar la compra.
Modelo de Producto models/Product.js Sequelize + PostgreSQL (tabla: products): nombre, precio, stock, variantes (JSONB: talla/color), imágenes (JSONB). Se decrementa stock al confirmar pedido.
Carrito de Compras (Frontend) models/appModel.js Métodos addToCart(), removeFromCart(), clearCart(), cartCount(): gestión de carrito con persistencia en localStorage, validación de stock, expiración de 2 horas.
Estrategia de Descuentos strategies/discount.js Patrón Strategy: cálculo de descuentos porcentuales aplicados al subtotal del carrito mediante códigos promocionales.
Estrategia de Pagos strategies/payment.js Patrón Strategy: procesamiento según método de pago seleccionado (transferencia bancaria, contra-entrega, MercadoPago con redirección).
Controlador de Checkout (Frontend) controllers/appController.js Orquesta flujo de compra: resumen del carrito, formulario de envío, selección de pago, aplicación de cupones, redirección a MercadoPago, manejo de retorno (_handleMPReturn).
Vista de Pedidos (Frontend) views/appView.js Renderizado del carrito, resumen de compra, seguimiento de pedidos, historial y detalle con factura.

Proceso 3: Gestión de Inventario

Elemento N3 Código (paquete/clase) Responsabilidad
Componente de Gestión de Inventario (Proveedores) routes/suppliers.js CRUD completo de proveedores (GET/POST/PUT/DELETE /suppliers): nombre, contacto, email, teléfono, dirección, ciudad, notas. Protegido con authRequired + adminOnly. Registra auditoría con logActivity().
Componente de Gestión de Inventario (Almacenes) routes/warehouses.js CRUD de almacenes y gestión de estanterías como JSONB. Endpoints adicionales: POST /:id/shelves (agregar estantería), DELETE /:id/shelves/:shelfId (eliminar). Protegido con adminOnly.
Componente de Gestión de Inventario (Albaranes) routes/purchaseOrders.js Ciclo completo de órdenes de compra con estados: borrador → enviado → parcial → completo → cancelado. Genera Nº secuencial (ALB-0001). Edición solo en estado borrador. POST /:id/receive: recepción de mercancía que actualiza stock del producto, crea movimientos de inventario (StockMovement), detecta discrepancias y puede auto-crear productos nuevos desde el albarán.
Componente de Gestión de Inventario (Movimientos y Alertas) routes/inventory.js GET /movements: consulta movimientos con filtros (productId, type, limit). GET /low-stock: alertas de productos con stock ≤ umbral configurable (evalúa stock general y por variante). POST /adjust: ajuste manual de stock (entrada/salida/ajuste absoluto) con registro de movimiento.
Modelo de Proveedor models/index.js (Supplier) Sequelize + PostgreSQL (tabla: suppliers): name, contactPerson, email, phone, address, city, notes, active, timestamps.
Modelo de Almacén models/index.js (Warehouse) Sequelize + PostgreSQL (tabla: warehouses): name, location, active, timestamps. Estanterías almacenadas como JSONB: shelves[{code, label}].
Modelo de Orden de Compra models/index.js (PurchaseOrder) Sequelize + PostgreSQL (tabla: purchase_orders): poNumber (unique), supplierId (ref Supplier), supplierName, status (enum: borrador/enviado/parcial/completo/cancelado), notes, expectedDate, totalCost. Items como JSONB: [{productId, productName, variantId, quantityOrdered, quantityReceived, unitCost, warehouseId, shelfId, receivedAt, isNewProduct, newProductData}].
Modelo de Movimiento de Stock models/index.js (StockMovement) Sequelize + PostgreSQL (tabla: stock_movements): productId, productName, variantId, variantLabel, type (entrada/salida/ajuste), quantity, reason, referenceType (purchase_order/customer_order/manual/return), referenceId, warehouseId, warehouseName, shelfCode, userId, userName, timestamps. Trazabilidad completa de cada cambio de inventario.
Vista de Inventario (Frontend) views/inventoryView.js Renderiza 6 secciones: proveedores, almacenes, albaranes (con badges de estado), detalle de albarán, formulario de recepción de mercancía, movimientos de stock y alertas de stock bajo (código de colores rojo/naranja). Incluye impresión PDF de albaranes.
Controlador de Inventario (Frontend) controllers/appController.js Orquesta menú lateral de inventario (5 secciones), carga datos de la API REST, gestiona eventos CRUD para proveedores, almacenes y albaranes. Maneja proceso de recepción de mercancía con asignación de almacén/estantería y transiciones de estado.
Componente de Seguridad middleware/auth.js authRequired + adminOnly aplicado en todas las rutas de inventario (/suppliers, /warehouses, /purchase-orders, /inventory). Garantiza que solo administradores acceden al módulo completo.
Auditoría de Inventario helpers/auditLog.js logActivity(): registra cada operación de inventario con action (CREATE/UPDATE/DELETE/RECEIVE_GOODS/STOCK_ADJUSTMENT), entity, entityId, entityName, usuario, timestamp y detalles adicionales (cambios, discrepancias, nuevo estado). Complementado por triggers PostgreSQL en db_changelog.
